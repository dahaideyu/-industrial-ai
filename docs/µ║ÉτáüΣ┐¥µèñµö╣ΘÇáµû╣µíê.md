# Python 源码保护改造方案

> ✅ **已实现**：Cython 编译 + 提示词加密 + `COMPILE_SOURCE` 参数控制。本地构建编译保护镜像，服务器部署无需源码。

## 背景

当前项目部署到服务器后，Python 源码（.py 文件）直接暴露在 Docker 容器中，存在源码泄露风险。本方案通过 Cython 编译，将 .py 文件转换为 .so 二进制文件，防止源码被直接查看。

## 方案选型

| 方案 | 保护强度 | 实现难度 | 性能影响 | 兼容性 | 备注 |
|------|---------|---------|---------|--------|------|
| **Cython（采用）** | ⭐⭐⭐ | 中 | 略有提升 | 需要适配 | 编译快，生态成熟 |
| Nuitka | ⭐⭐⭐⭐⭐ | 高 | 提升明显 | 需测试 | 过重，不适合本项目 |
| PyArmor | ⭐⭐⭐ | 低 | 几乎无 | 好 | **试用版有文件数限制，不适用** |
| 仅 .pyc | ⭐⭐ | 低 | 无 | 好 | 保护力度不足 |

**选择 Cython 的理由**：
1. Web 服务不需要独立可执行文件（Nuitka 的优势场景）
2. 编译速度快，CI/CD 流程顺畅
3. 体积增加小，镜像不会膨胀太多
4. 对 CPU 密集型任务有额外性能收益
5. 成熟稳定，numpy、pandas 等知名项目都在使用

**PyArmor 的问题**：
- 试用版只能混淆约 100 个文件，本项目有 200+ 文件，超出限制
- 商业授权需要付费

## Cython 兼容性问题及解决方案

Cython 对现代 Python 语法支持不完善，实际实施中遇到了以下问题：

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| `str \| None` 编译失败 | Cython 不支持 Python 3.10+ 联合类型语法 | 脚本自动转为 `Optional[str]` |
| `from __future__ import annotations` 崩溃 | Cython 的 memoryview 解析器不支持 | 脚本自动移除 |
| `UnicodeNode has no attribute 'start'` | 变量名 `long` 与 Cython C 类型关键字冲突 | 重命名为 `long_df` |
| 复杂 f-string 编译失败 | Cython 对含引号的 f-string 表达式处理有 bug | 脚本自动转为 `.format()` |
| `TypeError: Expected str, got Query` | Cython 用函数注解做类型检查，与 FastAPI 的 Query/Header 冲突 | 添加 `annotation_typing=False` 指令 |
| pandas 链式索引误判为 memoryview | Cython 类型推断把 `df[cond][["col"]]` 当类型声明 | 添加 `infer_types=False` 指令 |
| `sys` 变量未定义 | 改导入时误删了 `import sys` | 手动恢复 |
| 编译失败后源码被删除 | 原脚本无条件删除所有 .py | 改为只删除有对应 .so 的文件 |

所有兼容性问题由 `docker/scripts/fix_cython_compat.py` 脚本自动处理，在 Cython 编译前运行。

## 技术方案

### Dockerfile Stage 2.5

在 Stage 2（后端依赖）和 Stage 3（最终镜像）之间，新增 Cython 编译阶段：

```dockerfile
# ---- Stage 2.5: Cython 编译源码保护 ----
FROM python:3.12-slim AS code-protect
RUN apt-get update && apt-get install -y gcc python3-dev build-essential && \
    pip install cython -i https://pypi.tuna.tsinghua.edu.cn/simple
WORKDIR /build
COPY --from=backend-deps /app/.venv /app/.venv
ENV PATH="/app/.venv/bin:$PATH"
COPY backend/ ./backend/

# 自动修复 Cython 兼容性问题
COPY docker/scripts/fix_cython_compat.py /tmp/fix_cython_compat.py
RUN python /tmp/fix_cython_compat.py backend

# 编译所有 Python 文件（排除 __init__.py）
RUN echo "=== 开始 Cython 编译 ===" && \
    FAILED=0 && \
    for f in $(find backend -name "*.py" -not -name "__init__.py"); do \
        cython -3 "$f" -o "${f%.py}.c" && \
        gcc -shared -O2 -fPIC ... -lpython3.12 || { FAILED=1; }; \
    done && \
    if [ "$FAILED" = "1" ]; then exit 1; fi && \
    # 只删除已成功编译的 .py 文件
    for f in $(find backend -name "*.py" -not -name "__init__.py"); do \
        if [ -f "${f%.py}.so" ]; then rm "$f"; fi; \
    done
```

### 关键技术点

1. **保留 `__init__.py`** — Python 包结构依赖它
2. **Cython 指令** — 每个文件顶部自动添加 `# cython: annotation_typing=False, infer_types=False, language_level=3`
3. **编译失败不删除源码** — 只有编译成功（有对应 .so）的文件才删除 .py
4. **fix_cython_compat.py** — 自动处理类型注解、f-string、`from __future__` 等兼容性问题

## 提示词加密方案

### 原理

使用 Fernet 对称加密（AES-128-CBC + HMAC），将所有 `prompts/*.txt` 文件加密为单个 `prompts_encrypted.json`。

### 加密流程（构建时）

```bash
# 运行加密脚本
python scripts/encrypt_prompts.py

# 生成：
#   backend/prompts_encrypted.json   ← 密文（780KB，48 个文件）
#   输出：PROMPT_ENCRYPT_KEY=xxx     ← 密钥，配置到服务器 .env
```

### 解密流程（运行时）

```
容器启动 → 读取 PROMPT_ENCRYPT_KEY 环境变量
         → PromptLoader._init_cipher()
         → get_prompt("xxx.txt")
         → 优先读 .txt 明文 → 找不到 → 从 prompts_encrypted.json 解密
```

### 密钥管理

- 密钥**不在** Docker 镜像中
- 解密代码（`prompt_loader`）已编译为 `.so`，外部无法调用
- 构建时：脚本输出密钥 → 手动添加到服务器 `.env` 文件
- 运行时：通过 `env_file` 注入容器，`.so` 模块内部解密
- **双重保护**：单独拿到密钥或单独拿到密文都无法解密，必须同时拥有二者且在运行容器内

### Dockerfile 中的处理

```dockerfile
# Stage 3：如果存在加密文件，删除明文提示词
RUN if [ -f backend/prompts_encrypted.json ]; then \
        find backend -name "*.txt" -path "*/prompts/*" -delete && \
        echo "已删除明文提示词文件（使用加密版本）"; \
    fi
```

## 部署流程

### COMPILE_SOURCE 参数

```bash
# 生产构建（编译源码 + 加密提示词）
docker build -f docker/Dockerfile --build-arg COMPILE_SOURCE=true -t chaowei-agent:latest .

# 测试构建（跳过编译，快速调试）
docker build -f docker/Dockerfile --build-arg COMPILE_SOURCE=false -t chaowei-agent:latest .
```

docker-compose 中已配置默认值：

```yaml
args:
  COMPILE_SOURCE: "${COMPILE_SOURCE:-true}"   # 默认编译
```

测试环境覆盖为 `false`（`docker-compose.test.yml`）。

### 本地构建 → 服务器部署

```
本地：加密提示词 → Docker build（Cython 编译）→ docker save → tar
                         ↓
上传：tar + docker/ 配置目录
                         ↓
服务器：docker load → docker compose up（无需源码、无需 git clone）
```

**服务器上只需：**
- `chaowei-agent-latest.tar`（镜像）
- `docker/` 目录（compose 文件 + .env 配置）

**不需要：**源码、Dockerfile、git 仓库、构建脚本。

详细步骤见 [deploy-local-build.md](./deploy-local-build.md)。

## 注意事项

1. **首次构建时间增加** — Cython 编译 206 个文件约需 3-5 分钟
2. **调试困难** — 编译后的代码无法直接调试，建议本地用 `COMPILE_SOURCE=false` 快速迭代
3. **动态导入** — 使用 `importlib.import_module()` 的模块也需要被编译
4. **`__init__.py` 保留** — Python 包结构依赖它，52 个全部保留
5. **提示词密钥** — 必须与 .env 中的 `PROMPT_ENCRYPT_KEY` 一致，更换密钥需重新构建镜像
6. **换行符** — Windows 下 `entrypoint.sh` 可能被 git 转为 CRLF，需手动修复后构建
