# 早会日报第四份报告上游对接说明

## 一、对接结论

第四份《班次/班组绩效对比报告》由AI服务生成并保存，同时通过报告完成回调发送给上游。

上游系统需要：

- 不需要修改日报原始数据接口。
- 不需要增加 `teamScheduleContext`。
- 在报告完成回调中接收 `teamCompareMarkdown`。

## 二、报告完成回调

AI服务继续使用现有日报拉参数据中的白班、夜班信息生成第四份报告。

班组对应关系由AI服务读取本地临时配置；没有有效班组关系时，AI服务直接按照白班、夜班维度分析。

```http
POST /report/ai-agent/callback/complete
```

成功回调请求体增加 `teamCompareMarkdown`，例如：

```json
{
  "reportId": 10001,
  "status": "0",
  "markdownContent": "第一份基础日报",
  "summaryMarkdown": "第二份趋势分析",
  "kbReportMarkdown": "第三份改善建议",
  "teamCompareMarkdown": "第四份班次/班组绩效对比报告",
  "knowledgeBasePayload": "[]",
  "agentResponseRaw": "{\"reports\": []}"
}
```

失败回调仍按原有约定发送状态和错误信息，不填充报告内容字段。

## 三、第四份报告保存位置

第四份报告保存到AI服务自己的数据库：

```sql
team_compare_markdown TEXT
```

数据库字段与回调字段的对应关系为：

```text
team_compare_markdown -> teamCompareMarkdown
```

## 四、对接人需要了解的事项

上游需确认现有日报数据中的白班、夜班信息继续正常提供，并完成
`teamCompareMarkdown` 的接收与存储。

## 五、基地级开关

通过部署环境变量控制各基地是否启用第四份报告：

```dotenv
LEAN_MORNING_DAILY_FOURTH_REPORT_ENABLED=false
```

- `true`：生成第四份报告，并在成功回调中发送 `teamCompareMarkdown`。
- `false`（默认，变量缺失时也生效）：仅生成前三份报告，不注入班组排班数据，也不发送该字段。
