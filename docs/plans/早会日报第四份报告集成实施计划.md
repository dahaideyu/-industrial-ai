# 早会日报第四份报告集成实施计划

## 一、项目目标

在现有精益早会日报的三份报告基础上，新增第四份《班组组长绩效对比分析报告》，实现同一工序、相同设备范围、相同人员规模下白班与夜班的当日表现对比。

现有报告链路：

1. 基础日报
2. 趋势分析
3. 改善建议

调整后的报告链路：

1. 基础日报
2. 趋势分析
3. 改善建议
4. 班组组长绩效对比

第四份报告由大模型生成，主要比较设备效率、质量、产量、点检、报警和报修等指标，并将白班、夜班表现归属到相应班组及组长。

## 二、当前数据现状

### 2.1 日报原始数据

当前日报数据已包含部分班次信息：

- 设备运转率数据包含白班、夜班或“早班（单班次）”。
- 质量检验数据包含 `classType` 或检验发生时间。
- 点检、报警、报修等数据包含业务发生时间，可根据时间判断班次。
- 暂无 `teamId`、`teamName`、`leaderName` 等班组归属字段。

因此，日报数据可以反映白班和夜班表现，但暂时不能直接确定对应的班组和组长。

### 2.2 班组班次配置

现有班组班次配置包含：

- `lineId`、`lineName`
- `teamId`、`teamName`
- `schedulingDate`
- `classId`、`className`
- `scheduledDevices`
- 班组名称括号中的组长姓名

该配置可以提供以下映射关系：

```text
生产日期 + 产线 + 班次
          ↓
班组 + 组长 + 设备范围
```

## 三、现阶段总体方案

在日报拉参完成后、正式数据预处理前，加载班组班次配置，并将匹配结果注入日报数据：

```text
日报原始数据
        +
班组班次配置
        ↓
按生产日期、lineId、班次关联
        ↓
注入 teamScheduleContext
        ↓
执行现有数据预处理
        ↓
生成四份报告
```

前三份报告继续使用原有逻辑；第四份报告同时读取日报指标与 `teamScheduleContext`，生成班组组长对比结果。

班组配置匹配失败时，不影响前三份报告，第四份报告只说明班组数据缺失或不具备对比条件。

## 四、班组数据注入结构

在日报数据根节点增加：

```json
{
  "teamScheduleContext": {
    "productionDate": "2026-07-19",
    "lineId": 1,
    "mappingSource": "班组班次配置",
    "teams": [
      {
        "teamId": 3,
        "teamName": "铸带线A班组",
        "leaderName": "陈明浪",
        "classId": 1,
        "className": "白班",
        "classCode": "DAY",
        "devices": [
          {
            "deviceId": 118,
            "deviceName": "1#铸带线"
          }
        ]
      },
      {
        "teamId": 4,
        "teamName": "铸带线B班组",
        "leaderName": "陈昌武",
        "classId": 2,
        "className": "夜班",
        "classCode": "NIGHT",
        "devices": [
          {
            "deviceId": 118,
            "deviceName": "1#铸带线"
          }
        ]
      }
    ]
  }
}
```

正式接口提供班组字段前，组长姓名临时从班组名称括号中提取；正式数据接入后，应直接使用独立的组长ID和姓名字段。

## 五、班组配置读取方案

### 5.1 测试阶段

将班组配置保存为项目可读取的JSON文件，例如：

```text
backend/config/team_schedule.json
```

通过环境变量配置实际路径：

```text
TEAM_SCHEDULE_CONFIG_PATH=backend/config/team_schedule.json
```

测试阶段按月更新班组配置文件。

### 5.2 后续正式阶段

日报接口增加班组信息后，按以下优先级取值：

1. 优先使用日报原始数据中的班组信息。
2. 原始数据没有班组信息时，使用临时班组配置。
3. 两种来源都没有时，标记班组数据缺失。

该方式可以保证第四份报告提示词、数据库字段和展示逻辑保持不变，只替换班组信息来源。

## 六、班次关联规则

### 6.1 标准班次

统一转换为内部班次编码：

| 原班次 | 标准班次 |
|---|---|
| 白班、早班 | `DAY` |
| 夜班、晚班 | `NIGHT` |
| 早班（单班次） | `DAY`，但标记为单班制 |

### 6.2 关联主键

优先使用：

```text
生产日期 + lineId + deviceId + 标准班次
```

只有工序级数据时，使用：

```text
生产日期 + lineId + 标准班次
```

### 6.3 跨日夜班

夜班按生产日期归属：

```text
当日18:00—次日06:00 → 当日夜班
```

例如，2026-07-20 02:30发生的事件归属于2026-07-19夜班。

### 6.4 单班制

如果当日只有“早班（单班次）”数据，第四份报告应说明夜班无有效数据，不进行完整的白夜班组长绩效对比。

## 七、代码改造计划

### 7.1 新增班组配置处理模块

建议新增：

```text
backend/modules/lean_morning_daily/team_schedule.py
```

主要职责：

- 加载班组配置。
- 根据日期和 `lineId` 匹配排班。
- 标准化班次名称。
- 临时解析组长姓名。
- 生成 `teamScheduleContext`。
- 将班组上下文注入日报数据。
- 校验重复排班及设备范围。

建议函数：

```python
load_team_schedule_config()
normalize_class_name()
extract_leader_name()
build_team_schedule_context()
inject_team_schedule_context()
```

### 7.2 修改日报Worker

修改：

```text
backend/modules/lean_morning_daily/worker.py
```

在日报拉参成功后、历史数据加载和日报预处理前执行：

```python
payload = inject_team_schedule_context(payload)
```

容错要求：

- 配置文件缺失：记录告警，继续前三份报告。
- 当前日期无排班：记录告警，第四份说明缺少数据。
- 当前产线无排班：不进行跨产线猜测。
- 班次重复匹配：标记数据异常，不强行归属。

### 7.3 新增第四份提示词

新增：

```text
backend/modules/daily_report/prompts/lean_morning_daily_report04.txt
```

第四份报告输出结构：

1. 当日对比结论
2. 核心指标对比
3. 设备表现对比
4. 质量、点检与设备异常
5. 两位组长当班表现
6. 次日改善建议
7. 数据口径说明

提示词必须约束：

- 只能使用输入数据。
- 无数据不能当作0。
- 百分率差异使用“百分点”。
- 不擅自将设备故障认定为组长责任。
- 历史报修不作为当班新增报修。
- 没有两个有效班次时不强行对比。
- 不设置无依据的综合评分。

### 7.4 修改报告模板配置

修改：

```text
backend/config/report_templates.yaml
```

在精益早会日报配置中增加：

```yaml
- template: "lean_morning_daily_report04.txt"
  output_name: "班组组长绩效对比"
  use_raw_data: true
  use_ragflow: false
```

第四份报告直接使用预处理后的原始日报数据，不依赖前三份报告内容。

### 7.5 调整报告字段映射

第四份报告映射为：

```text
第1份 → markdownContent
第2份 → summaryMarkdown
第3份 → kbReportMarkdown
第4份 → teamLeaderMarkdown
```

需要同步调整：

- `_map_to_callback_fields()`。
- 生成数量日志。
- 报告错误兜底。
- 最终任务返回结果。
- 傍晚版只生成第一份报告时的跳过逻辑。

```sql

ADD COLUMN IF NOT EXISTS team_leader_markdown TEXT;
```

## 十三、验收标准

- 同一工序的白班、夜班可以正确关联到班组和组长。
- 第四份报告可以独立生成并保存。
- 白夜班核心指标、相同设备和异常事件对比准确。
- 缺少班组或班次数据时不虚构结论。
- 前三份报告行为保持不变。
- 傍晚版和其他报告类型不受影响。
- 数据库可以保存并更新第四份报告。
- 上游支持后可以正确接收第四份报告字段。
- 自动化测试和现有回归测试通过。
