# 需求文档目录

> 本目录统一存放正在进行中的需求文档，用于团队成员了解需求范围、当前完成状态、待用户确认的功能点以及已知问题，便于其他同事快速接手并接着开发。

## 目录约定

每份需求文档至少包含以下章节：

| 章节 | 用途 |
|------|------|
| 需求概述 | 用 1-2 段话讲清楚这个需求要解决什么问题、面向哪些用户 |
| 子功能列表 | 拆解为可独立验收的子功能（用 ✅ / ⏳ / ❌ 标记状态） |
| 完成状态 | 整体进度 + 各子功能的具体状态 |
| 待用户确认的功能 | 列出已完成但用户**还没正式确认验收**的功能点 |
| 已知问题 | 用户反馈过的 Bug 或阻塞点，含初步定位 |
| 相关代码位置 | 列出主要的前后端文件路径，方便快速入手 |
| 最后更新 | 文档最后修改时间 |

状态图例：

- ✅ 已完成且用户已确认
- ⏳ 已开发完成，等待用户确认
- 🛠 开发中
- ❌ 未开始
- 🐛 有问题/待修复

## 如何使用

1. **接手新需求**：先看「需求概述」「子功能列表」了解全貌，再看「已知问题」避免踩坑。
2. **更新需求进度**：每完成一个子功能，把对应状态从 🛠 改成 ⏳（待用户确认）或 ✅（已确认）。
3. **记录新问题**：用户反馈新 Bug 时立刻补到对应文档的「已知问题」章节，附上复现步骤和初步定位。
4. **需求变更**：用户改需求时，先在「待用户确认的功能」或新增「需求变更记录」章节记录，再开始改代码。
