## 产品简介

工业数据智能问答平台是一个面向工业场景的 NL2SQL（自然语言转 SQL）智能问答系统。用户可以用日常自然语言直接查询数据库中的设备、产线、维修工单、点检记录等核心业务数据，系统会自动将问题转化为 SQL 查询并返回结果。此外，平台还能融合设备手册、维修文档等知识库进行辅助问答。

**核心能力：**

- **自然语言查数据**：像和人对话一样提问，无需懂 SQL 或数据库结构
- **文档智能检索**：自动从设备手册、SOP 文档中找到相关答案
- **智能消歧**：自动识别简称、同音字、别名等模糊表述
- **持续学习**：通过用户反馈和管理员训练持续提升准确率

**适用场景：**

- 查设备状态、产线信息
- 统计各产线设备数量、故障率等指标
- 查询维修工单、点检记录
- 搜索设备操作手册、故障处理指南

## 方案设计

### 整体架构

平台采用 B/S 架构，用户通过浏览器访问，后端自动完成问题理解、SQL 生成、数据查询和结果汇总。

```
浏览器 (用户界面)
    │
    ▼
后台服务 (FastAPI)
    │
    ├── 意图分析：判断用户想问什么类型的问题（6种意图）
    ├── 实体消歧：识别问题中的设备名、产线名（支持多选）
    ├── 通用问答：闲聊、概念解释等无需查库的问题
    ├── 记忆检索：查找相似的历史问答 + 对话历史作为参考
    ├── SQL 生成：将自然语言转为 SQL 语句（支持多条 SQL 顺序执行）
    ├── 安全检查：确保 SQL 不会修改数据
    ├── 数据库查询：执行 SQL 获取结果
    ├── 数据分析：对查询结果进行推理，生成洞察和图表
    └── 结果汇总：将数据转为自然语言回答
```

### 处理流程

当用户提出一个问题后，系统会按以下流水线自动处理：

```
用户提问 → 意图分类 → 实体消歧 → 记忆检索 → SQL 生成 → 安全检查 → 执行查询 → 结果汇总
```

每一步都是可观测的——用户可以实时看到当前进展到了哪一步，以及每步的耗时。

### 问题类型

系统会根据问题内容自动判断属于哪种类型，并采用不同的处理方式：

| 类型 | 说明 | 示例 |
|------|------|------|
| 简单事实查询 | 查询具体信息 | "和膏产线有哪些设备" |
| 聚合统计 | 统计数量、求和等 | "各产线设备数量统计" |
| 多跳关联 | 跨表关联分析 | "近30天故障率最高的产线" |
| 文档查询 | 查手册、SOP 等 | "和膏机温度过高怎么处理" |
| 通用问答 | 闲聊或概念解释 | "你是谁"、"OEE怎么计算" |
| 数据分析 | 数据洞察和图表 | "分析制带线故障趋势" |

### 关键技术

- **NL2SQL**：使用 Vanna 框架 + DeepSeek 大语言模型，将自然语言自动转换为 SQL 查询
- **向量记忆**：使用 ChromaDB 存储历史问答对和表结构，检索最相关的上下文辅助 LLM 生成
- **实体消歧**：结合向量检索和 LLM 判断，自动识别用户提到的设备、产线等实体
- **RAGFlow 集成**：接入 RAGFlow 文档知识库，支持设备手册、维修文档等内容的智能检索

## 核心功能

### 智能问答 (NL2SQL)

**用自然语言查询数据库，无需编写 SQL。**

**使用方式：**

1. 在底部输入框输入问题
2. 按 Enter 发送
3. 系统自动执行以下流程：
   - **意图分析**：理解你想查什么类型的数据
   - **实体消歧**：识别你提到的设备、产线
   - **记忆检索**：查找相关的历史问答作为参考
   - **SQL 生成**：自动生成正确的 SQL 查询
   - **安全检查**：确保查询不会修改数据
   - **数据库查询**：执行查询获取结果
   - **结果汇总**：将数据转化为自然语言回答

**提问技巧：**

- 尽量使用完整的句子，而不是关键词
- 明确指定要查询的实体名称，如产线名、设备名
- 模糊查询也可以，系统会自动消歧

**示例问题：**

| 问题 | 系统会做什么 |
|------|-------------|
| 和膏产线有哪些设备 | 查询 sys_line 表中和膏相关产线，关联 dev_device 表列出设备 |
| 各产线的设备数量 | 按产线分组统计设备数，生成聚合查询 |
| 正1#和膏机最近的维修记录 | 多表关联查询维修工单 |
| 上周故障最多的设备 | 按设备分组统计，排序取 TOP |

### 文档问答 (RAG)

当系统判断你的问题涉及操作手册、故障处理、SOP 等文档知识时，会自动切换到文档检索模式，从 RAGFlow 知识库中查找相关文档并生成回答。

**适用场景：**

- 设备故障处理方法
- 维修操作指南
- 设备维护手册查询
- SOP 标准操作规程

**使用方式：**

不需要手动切换，直接在输入框提问即可。例如：
- "和膏机温度异常怎么处理"
- "制带机的操作规程是什么"

系统识别到文档类问题后，会自动检索知识库并返回答案，答案中会标注引用的文档来源。

### 实体消歧

当你问题中的实体名称比较模糊时（如简称、同音字），系统会自动进行消歧处理。

**自动消歧：** 系统能直接匹配到对应实体时，自动完成消歧，无需用户参与。

**交互消歧：** 当系统不确定你指的是哪个实体时，会在聊天中弹出**选项卡片**：
1. 系统显示找到的候选实体列表（含关系链上下文，如"1#制带线 → 制带车间 → 生产部"）
2. 你可以**单选**或**多选**实体（checkbox），多选时自动生成 OR 条件
3. 点击「确认选择，继续查询」
4. 系统使用确认后的实体继续执行查询

**实体类型：**

| 类型 | 说明 | 示例 |
|------|------|------|
| 产线 | 生产线 | "和膏产线"、"装配线" |
| 设备 | 机器设备 | "和膏机"、"制带机" |
| 自定义指标 | 业务指标 | "OEE"、"故障率" |

### 多会话管理

支持同时维护多个对话，每个对话有独立的上下文。会话数据存储在服务器端，换设备登录后仍可查看历史记录。

**操作：**

- **新建会话**：点击左侧边栏顶部的 "+" 按钮
- **切换会话**：点击会话列表中的会话名称
- **重命名会话**：双击会话标题可编辑
- **删除会话**：鼠标悬停在会话上，点击右侧出现的删除按钮
- **自动保存**：所有会话自动保存到服务器，换浏览器或设备登录后仍可访问

### 执行过程可视化

每次查询后，系统会展示完整的执行过程，帮助你了解系统是如何工作的。

**步骤列表：**

每次查询会依次执行多个步骤，每一步都有对应的状态图标：
- 🔄 进行中
- ✅ 完成
- ❌ 错误

**交互方式：**

- **处理中**：步骤列表实时更新，可以看到当前正在执行哪一步
- **完成后**：自动折叠为摘要栏，显示"回答完毕 · 8/8 步 · 总耗时 32.5s"
- **展开详情**：点击摘要栏查看每步的具体内容和耗时
- **再次点击**：收起摘要

每步会显示具体的耗时（毫秒），方便发现性能瓶颈。

### 结果展示与反馈

系统会根据查询结果类型自动选择最合适的展示方式：

**统计卡片：** 当查询结果是计数类（如"有多少台设备"），以卡片形式展示大号数字。

**数据表格：** 当结果包含多行数据时，以表格形式展示，支持：
- 点击表头排序
- 输入关键词筛选
- 点击单元格复制内容

**SQL 详情：** NL2SQL 回答下方有折叠的 SQL 区域，点击可查看系统自动生成的 SQL 语句。复杂问题会自动拆分为多条 SQL 顺序执行。

**数据洞察：** 当查询结果有分析价值时，回答末尾显示 `💡 输入「分析一下」可获取深度数据洞察` 提示。输入后系统进行深度分析并生成：

- **自然语言洞察**：2-4 句话的业务结论（趋势、异常、占比）
- **图表展示**：柱状图（类型对比）、折线图（时间趋势）、饼图（占比分布）

**用户反馈：**

每条 NL2SQL 回答下方有反馈按钮，帮助系统持续提升准确率：

- **正确**：点击 👍，该问答对自动保存到记忆库供管理员审核
- **错误**：点击 👎，输入错误原因，反馈记录到审核队列（不再重新生成 SQL），管理员审核修正后入库训练

### 通用问答

对于不涉及数据库查询的问题，系统自动路由到通用问答 Agent：

- **闲聊**："你是谁"、"你能做什么"
- **概念解释**："OEE是怎么计算的"、"设备综合效率是什么"
- **指标查询**：自动检索平台中自定义的业务指标定义（如 OEE 计算公式），基于定义回答

### 数据分析

系统支持对查询结果进行深度数据分析：

**自动触发**：问题包含分析意图时（如"分析故障趋势"），查询后自动进入数据分析 Agent。

**手动触发**：普通查询后，如果数据有多维度可比性（>1行、含分类/时间列），回答末尾会提示「输入分析一下」。用户输入后，系统基于上次查询结果进行推理。

**图表类型**：
| 图表 | 适用场景 |
|------|---------|
| 柱状图 | 类型对比、排名（如各故障类型频次） |
| 折线图 | 时间趋势（如每日故障数变化） |
| 饼图 | 占比分布（如各车间故障占比） |

### 对话记忆

系统会自动记住当前会话中的历史问答，在生成 SQL 和实体识别时自动带入上下文：

- **指代消解**：追问"那正冲网呢"时，自动理解是问同类型的查询
- **最多保留 5 对问答**，避免上下文过长

## 管理后台

管理后台用于训练和维护系统，确保 NL2SQL 的准确性。

**进入方式：** 点击左侧边栏底部的「管理后台」按钮。

管理后台包含 4 个主要模块（记忆库管理、手动训练、训练审核、效果监控），以及侧边栏的数据库索引和实体管理入口：

### 数据库索引

**功能：** 让系统知道数据库中有哪些表、每个表有哪些字段。

**为什么需要：** LLM 本身不知道你的数据库结构，需要将表结构信息告诉它，才能生成正确的 SQL。

**操作步骤：**

1. 进入管理后台 → 数据库索引
2. 页面显示所有数据库表及其索引状态（已索引/未索引）
3. 勾选需要让系统能查询的表（可多选）
4. 点击「索引选中表」
5. 不需要的表可点击「取消索引」

**建议：** 首次使用先索引核心业务表（如产线表、设备表、维修工单表等），只索引需要的表，避免无关表干扰。

### 手动训练

**功能：** 手动添加训练数据，让系统学习正确的查询方式。

**两种训练类型：**

**SQL 对训练：**
- 输入典型问题和对应的正确 SQL 语句
- 保存后直接进入记忆库
- 示例：问题"和膏产线有多少设备"→ SQL"SELECT COUNT(*) FROM dev_device WHERE line_id IN (SELECT id FROM sys_line WHERE name LIKE '%和膏%')"

**文档训练：**
- 输入业务规则、字段说明等文本
- 如"del_flag=0 表示有效数据，所有查询都需要加上这个条件"

### 训练审核

**功能：** 审核用户通过"正确"反馈提交的问答对。

当用户在前端点击"正确"反馈后，该问答对会自动进入审核队列。管理员需要审核这些条目：

- **批准**：确认无误，正式入库
- **编辑**：修正问题描述或 SQL 后入库
- **删除**：不合格的条目直接移除

### 记忆库管理

**功能：** 查看、搜索、编辑、删除已入库的记忆条目，支持批量操作和导入导出。

**筛选方式：**

- 全部类型：查看所有记忆
- SQL 对：仅查看问题-SQL 对
- 文档：仅查看文档类记忆
- 搜索框：输入关键词搜索（同时检索问题、SQL、文档内容）

**批量操作：**

- 勾选表格左侧 checkbox 可多选条目
- 选中后显示批量操作栏："已选 N 项" + "删除所选" + "导出所选"
- 表头 checkbox 可全选/取消全选当前页

**导入导出：**

- **导出全部**：弹出确认对话框后导出当前筛选类型的所有数据为 JSON
- **导出所选**：将选中的条目导出为 JSON 文件
- **导入 JSON**：选择之前导出的 JSON 文件导入，**Merge 模式**（与已有数据重复的条目自动跳过，不重复添加）

**注意：** 记忆库管理不显示待审核条目，审核通过后才会在此出现。

### 实体管理

**功能：** 管理实体别名、业务指标、实体索引。

**别名管理：**
- 为实体添加别名映射，处理简称、同音字等
- 例如："合膏线" → "和膏产线"、"1号机" → "正1#和膏机"
- 减少实体消歧时需要用户手动确认的情况

**指标管理：**
- 定义自定义业务指标
- 如 OEE、故障率、MTTR 等
- 包含指标名称、描述、SQL 表达式、关联实体类型、关键词

**实体工具：**
- 搜索测试：输入关键词测试实体检索结果
- 重建索引：修改数据库数据后重建向量索引

### 效果监控

**功能：** 查看平台使用统计和效果指标。

- 总查询次数、成功次数、成功率
- 意图分类分布（各类问题的占比）
- 平均响应时间、各步骤耗时

## 训练流程

为了让 NL2SQL 效果达到最佳，建议按以下顺序完成训练：

### 第一步：安装中文嵌入模型

首次使用需安装中文嵌入模型以支持中文语义搜索（由管理员在服务器端操作）。

### 第二步：索引数据库表结构

管理后台 → 数据库索引 → 勾选核心业务表 → 点击索引

### 第三步：添加实体别名

管理后台 → 实体管理 → 别名管理 → 添加常见简称、同音字映射

### 第四步：添加自定义指标

管理后台 → 实体管理 → 指标管理 → 定义业务指标及 SQL 表达式

### 第五步：手动训练

管理后台 → 手动训练 → 注入典型问题-SQL 对和业务规则文档

### 第六步：用户反馈积累

日常使用中，用户点击"正确"反馈 → 管理员在"训练审核"中审核入库 → 持续优化

### 最佳实践

1. **问题-SQL 对**：覆盖不同类型的查询（计数、列表、关联、聚合），每种 3-5 个示例
2. **文档训练**：重点描述字段含义、表关联关系、特殊查询规则
3. **实体别名**：重点添加常见简称、同音异字、习惯叫法
4. **表结构索引**：只索引业务查询需要的表，无关表会干扰 LLM 判断
5. **及时审核**：定期处理审核队列，保持记忆库质量

## 常见问题

### Q: 为什么提问后回答不准确？

按以下顺序排查：
1. 是否索引了相关表的表结构？（管理后台 → 数据库索引）
2. 是否添加了足够的训练示例？（管理后台 → 手动训练）
3. 问题中的实体是否被正确识别？（查看实体消歧结果）
4. 尝试用更明确的表述重新提问

### Q: 结果中为什么总是有 del_flag=0 的条件？

系统自动为产线表和设备表过滤已逻辑删除的数据（del_flag=0），确保只查询有效记录。

### Q: 实体消歧弹出了很多选项怎么办？

系统对用户提到的实体不确定时会弹出候选列表。选择正确的选项后确认即可。要减少此类情况，可在实体管理中为常见简称添加别名。

### Q: 如何查看当前索引了哪些表？

管理后台 → 数据库索引，页面列出所有表及其索引状态。

### Q: 记忆库管理和训练审核有什么区别？

- **训练审核**：展示用户通过"正确"反馈提交的待审核问答对
- **记忆库管理**：展示已审核通过的正式记忆条目，支持编辑和删除

### Q: 如何重置训练数据？

1. 管理后台 → 记忆库管理 → 勾选需要删除的条目 → 点击"删除所选"（或全选后批量删除）
2. 管理后台 → 数据库索引 → 取消所有索引
3. 管理后台 → 实体工具 → 重建索引

### Q: 会话数据会丢失吗？

所有会话保存在服务器数据库中。即使更换浏览器或设备，只要使用同一账号登录，历史会话仍然可用。清除浏览器缓存不会丢失会话数据。

### Q: 支持哪些类型的数据库查询？

系统只支持 SELECT 查询（只读）。任何修改数据的操作（增删改）都会被自动拦截，确保数据安全。
