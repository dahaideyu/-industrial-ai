# 超威 AI 离线部署说明

从本地 `build.bat` 打包到服务器上跑起来的完整操作流程。

---

## 一、build.bat 做了什么

在本地开发机上执行 `build.bat [版本号]`（如 `build.bat 1.2.0`），自动完成：

| 步骤 | 操作 | 产物 |
|------|------|------|
| 0 | 加密提示词（生成 key + 加密所有 prompts/\*.txt） | `prompts_encrypted.json` + 密钥写入 `build_key.txt` |
| 1 | 构建应用 Docker 镜像（含 Cython 源码编译） | `industrial-ai:<版本>` |
| 2 | 拉取 TimescaleDB 官方镜像 | `timescale/timescaledb:2.19.1-pg14` |
| 3 | 两个镜像一起导出到 tar | `industrial-ai-<版本>-bundle.tar` |
| 4 | 读取密钥文件并打印到终端 | 终端显示 `PROMPT_ENCRYPT_KEY=…`，随后删除 `build_key.txt` |

**最终产物**：
- `industrial-ai-<版本>-bundle.tar`（约 2~4GB）
- 终端输出的 `PROMPT_ENCRYPT_KEY`（密钥每次构建都会变，**必须复制保存**，部署时需要写入服务器 `.env`）

> `build_key.txt` 在 build.bat 执行完会自动删除，只会留在终端输出里。如果不小心关掉了终端，
> 可以重新跑一次 `build.bat`，key 会重新生成。

## 二、需要上传到服务器哪些文件

| 文件 | 用途 | 是否必须 |
|------|------|----------|
| `industrial-ai-<版本>-bundle.tar` | Docker 镜像包 | ✅ 必须 |
| `docker-compose.yml` | 基础 compose 配置 | ✅ 必须 |
| `docker-compose.test.yml` | 测试环境覆盖配置 | 测试环境需要 |
| `docker-compose.prod.yml` | 生产环境覆盖配置 | 生产环境需要 |
| `docker-compose.shandong.yml` | 山东基地覆盖配置 | 山东基地需要 |
| `docker-compose.jiangxi.yml` | 江西基地覆盖配置 | 江西基地需要 |
| `docker-compose.changxing.yml` | 长兴基地覆盖配置 | 长兴基地需要 |
| `docker-compose.weifu.yml` | 威孚基地覆盖配置 | 威孚基地需要 |
| `.env.example` | 环境变量模板 | ✅ 必须（参考创建 .env） |

```bash
#   deploy/docker/docker-compose.yml  →  /opt/chaowei-agent/deploy/docker/
#   deploy/docker/docker-compose.prod.yml   →  /opt/chaowei-agent/deploy/docker/
#   deploy/docker/docker-compose.test.yml   →  /opt/chaowei-agent/deploy/docker/
#   deploy/docker/docker-compose.shandong.yml → /opt/chaowei-agent/deploy/docker/
#   deploy/docker/docker-compose.jiangxi.yml  → /opt/chaowei-agent/deploy/docker/
#   deploy/docker/docker-compose.changxing.yml → /opt/chaowei-agent/deploy/docker/
#   deploy/docker/docker-compose.weifu.yml    → /opt/chaowei-agent/deploy/docker/
#   deploy/docker/.env.example  →  /opt/chaowei-agent/deploy/docker/
#   deploy/docker/.env.prod     →  /opt/chaowei-agent/deploy/docker/  （如果有）

#   deploy/docker/scripts/      →  /opt/chaowei-agent/deploy/docker/scripts/
```

## 三、服务器上的操作

### 3.0 停止旧版本容器

**如果服务器上已经有旧版本在跑，必须先停掉**，否则端口冲突起不来：

```bash
cd /opt/chaowei-agent/deploy/docker

# 先看当前有哪些容器在跑
docker compose ps
# 或者
docker ps | grep -E "industrial-ai|postgresql|redis|minio|repair-suggestion|mqtt-etl|knb-"

# 查看之前是用什么 compose 文件和 profile 启动的
docker compose ls

# 停掉旧容器（数据卷保留，不会丢数据）
docker compose down

# 重要：如果上次启动加了 -f 环境文件或 --profile，停的时候也要加上同样的参数！
# 比如上次是这样起的：
#   docker compose -f docker-compose.yml -f docker-compose.prod.yml --profile local-db --profile mqtt up -d
# 停的时候也必须：
#   docker compose -f docker-compose.yml -f docker-compose.prod.yml --profile local-db --profile mqtt down
# 否则 compose 会因为找不到某些服务而报错退出，实际可能没停干净。
```

> ⚠️ **不要**加 `-v`：`docker compose down -v` 会删光所有数据卷（PG 数据、MinIO 文件全丢）。
> 正常更新镜像只需要 `down`（不加 -v），然后加载新镜像 `up -d` 即可，数据保留。

确认全部停掉：
```bash
docker ps | grep -E "industrial-ai|postgresql|redis|minio|repair-suggestion|mqtt-etl|knb-"
# 应该没有任何输出
```

### 3.1 加载新镜像

```bash
cd /opt/chaowei-agent
docker load -i industrial-ai-1.2.0-bundle.tar
```

验证：
```bash
docker images | grep industrial-ai
# 应该看到新加载的 industrial-ai:1.2.0

docker images | grep timescaledb
# 应该看到 timescale/timescaledb:2.19.1-pg14
```

### 3.2 创建/更新 .env 配置文件

```bash
cd /opt/chaowei-agent/deploy/docker

# 首次部署：从模板复制
cp .env.example .env

# 或者从对应环境的预置文件复制：
# cp .env.test .env       # 测试环境
# cp .env.prod .env       # 生产环境
# cp .env.prod.changxing .env  # 长兴基地
# cp .env.prod.shandong .env   # 山东基地
# cp .env.prod.jiangxi .env    # 江西基地
# cp .env.prod.weifu .env      # 威孚基地
```

**然后用 vim 编辑 `.env`，至少改以下内容：**

```ini
# ⚠️ 必改项：

# 1. 模型配置（二选一）
PROVIDER=deepseek
DEEPSEEK_API_KEY=你的真实key

# 2. 数据库 — 如果连外部 PG 服务器
PG_HOST=10.1.2.227
PG_PORT=5432
PG_DB=knowledge_base
PG_USER=zxzz
PG_PASSWORD=真实密码

# 3. 数据库 — 如果使用容器自带 TimescaleDB（不连外部）
PG_HOST=postgresql
PG_PORT=5432
PG_USER=zxzz
PG_PASSWORD=Admin@Zxzz

# 4. 提示词加密密钥（build.bat 终端输出的那个，必须填！）
PROMPT_ENCRYPT_KEY=xxxxxxxxxx
PROMPT_SOURCE=encrypted

# 5. 镜像标签（必须和 build.bat 打包的版本一致）
IMAGE_NAME=industrial-ai
IMAGE_TAG=1.2.0

# 6. MQTT（如果用 MQTT ETL 采集数据）
MQTT_BROKER=10.x.x.x
MQTT_PORT=1883
MQTT_TOPIC=Gycs/chaowei/xxx

# 7. 上游系统
UPSTREAM_BASE_URL=10.1.2.116:18081
UPSTREAM_SECRET=ABCDEFGHIJJJ

# 8. RAGFlow 知识库（如果有外部 RAGFlow 实例）
RAGFLOW_BASE_URL=http://10.x.x.x:9380
RAGFLOW_API_KEY=真实的key
RAGFLOW_DATASET_ID=真实的dataset_id
```

### 3.3 启动新版本容器

启动命令**必须和停容器时用的 compose 文件和 profile 完全一致**。

```bash
cd /opt/chaowei-agent/deploy/docker

# 先设置镜像 tag（每次启动都要，或直接写进 .env）
export IMAGE_TAG=1.2.0

# --- 按环境对号入座 ---

# 测试环境 + 外部 PG
docker compose -f docker-compose.yml -f docker-compose.test.yml up -d

# 生产环境 + 外部 PG
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d

# 生产环境 + 自带 PG + MQTT
docker compose -f docker-compose.yml -f docker-compose.prod.yml --profile local-db --profile mqtt up -d

# 山东基地
docker compose -f docker-compose.yml -f docker-compose.shandong.yml up -d

# 长兴基地
docker compose -f docker-compose.yml -f docker-compose.changxing.yml up -d

# 江西基地
docker compose -f docker-compose.yml -f docker-compose.jiangxi.yml up -d

# 威孚基地
docker compose -f docker-compose.yml -f docker-compose.weifu.yml up -d
```

> 不加 `--build`：镜像名（`industrial-ai:1.2.0`）已匹配 `.env` 的 `IMAGE_NAME`/`IMAGE_TAG`，
> compose 直接复用 load 进来的镜像，不会在服务器上重新构建。

### 3.4 确认启动状态

```bash
# 看所有容器状态（都要是 Up / healthy）
docker compose ps

# 看日志，确认无异常
docker compose logs -f --tail=50 industrial-ai
```

### 3.5 访问验证

```text
http://服务器IP:9300
```

## 四、首次部署的额外操作（一次性）

### 4.1 同步设备字典表

全新环境首次启动后，PG 里设备字典表是空的，需要从 MySQL 同步：

```bash
docker cp deploy/docker/scripts/sync_device_dict.py industrial-ai:/tmp/
docker exec industrial-ai python /tmp/sync_device_dict.py
```

- 幂等，可重复执行
- 需要 MySQL（jxcw 业务库）可达

### 4.2 贝特瑞（BTR）现场设备核对（仅 BTR 现场需要）

```bash
docker cp deploy/docker/scripts/sync_btr_device_dict.py industrial-ai:/tmp/
docker exec industrial-ai python /tmp/sync_btr_device_dict.py
```

## 五、升级更新完整流程

```
本地开发机                      服务器
─────────                      ────────
build.bat 1.2.0
记录 PROMPT_ENCRYPT_KEY
  ↓
拷贝 tar + compose 配置
  + .env 文件 ───────────────→  docker compose down    ← 停旧容器（不加 -v）
                                 docker load -i xxx.tar ← 加载新镜像
                                 vim .env 更新密钥/tag
                                 docker compose up -d    ← 启动新容器
                                 docker compose ps       ← 确认状态
```

## 七、常用运维命令

```bash
# 重启单个服务
docker restart industrial-ai

# 查看某个容器日志
docker logs -f --tail=100 industrial-ai

# 停掉所有服务（数据卷保留，日常升级用这个）
docker compose down

# 停掉并删除数据卷（⚠️ 不可逆，数据全丢）
docker compose down -v

# 更新 .env 配置后重启相关容器
vim .env
docker restart industrial-ai repair-suggestion knb-celery-worker

# 进容器调试
docker exec -it industrial-ai bash
```

## 八、常见问题

### Q1: docker load 后 compose up 还在重新构建？

`.env` 里 `IMAGE_NAME` 和 `IMAGE_TAG` 必须跟 build.bat 打包时完全一致：

```ini
IMAGE_NAME=industrial-ai
IMAGE_TAG=1.2.0    # 改成你打包的版本
```

### Q2: docker compose down 报 "service xxx not found"

停容器时必须带上和启动时**完全相同**的 `-f` 环境文件和 `--profile`。如果忘了当时怎么起的，用 `docker compose ls` 查看。

### Q3: 启动后前端页面空白 / 提示词不显示？

检查 `.env` 里 `PROMPT_ENCRYPT_KEY` 是否跟 build.bat 输出的密钥一致。
每次重新 build 都会生成新 key，必须同步更新服务器 .env。

### Q4: MQTT ETL 数据写不进 PG？

确认 .env 里 `PG_HOST` 的值：
- 容器化部署：`PG_HOST=postgresql`（容器网络内用服务名直连）
- 宿主机裸跑：`PG_HOST=127.0.0.1`，`PG_PORT=15432`

### Q5: 知识库模块连不上 PG？

确认 .env 中 `PG_HOST`/`PG_PORT`/`PG_DB`/`PG_USER`/`PG_PASSWORD` 都正确填写，且 PG 服务允许该 IP 连接。
